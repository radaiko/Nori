WGSL Pipeline Index — Nori.GPU
================================================================================================
Maps each of the 23 original GLSL pipelines to their WGSL equivalents.

Geometry shader expansion strategy:
  Lines    → Instanced quads (6 verts/instance via vertex_index), endpoints as per-instance data
  Points   → Instanced quads (6 verts/instance via vertex_index), center as per-instance data
  Text     → Instanced quads (6 verts/instance via vertex_index), char box as per-instance data

Tessellation shader strategy:
  Bezier2D → CPU pre-tessellation via Poly.Flatten(), then same pipeline as Line2D

Bind Group Layouts
================================================================================================

Group 0 — Per-pipeline uniforms (all pipelines):
  @binding(0)  var<uniform> uniforms    Uniform buffer with pipeline-specific struct

Additional bindings for specific pipelines:
  DashLine2D:
    @binding(1)  var ltype_texture       texture_2d<f32>   Line-type pattern texture
    @binding(2)  var ltype_sampler       sampler           Sampler for line-type texture
  TextPx, Text2D, Text3D:
    @binding(1)  var font_texture        texture_2d<f32>   Font glyph atlas
    @binding(2)  var font_sampler        sampler           Sampler for font texture

================================================================================================
Vertex Buffer Layouts (per pipeline)
================================================================================================

Instanced line pipelines (Line2D, Line3D, BlackLine, GlassLine, DashLine2D, Bezier2D):
  Buffer 0, step=instance:
    @location(0) p0  — vec2<f32> or vec3<f32>  (8 or 12 bytes)
    @location(1) p1  — vec2<f32> or vec3<f32>  (8 or 12 bytes)
  No vertex buffer (vertices generated from vertex_index 0..5)

Instanced point pipelines (Point2D, Point3D):
  Buffer 0, step=instance:
    @location(0) pos — vec2<f32> or vec3<f32>  (8 or 12 bytes)
  No vertex buffer (vertices generated from vertex_index 0..5)

Direct triangle pipelines (Triangle2D, Quad2D, TriFanStencil, TriFanCover):
  Buffer 0, step=vertex:
    @location(0) pos — vec2<f32>  (8 bytes)

3D facet pipelines (Gourad, Phong, PhongPink, Pick, Glass, FlatFacet):
  Buffer 0, step=vertex:
    @location(0) position — vec3<f32>  (12 bytes, padded to 16 for alignment)
    @location(1) normal   — vec3<f32>  (12 bytes, via Vec3H expanded to f32)

Instanced text pipelines (TextPx):
  Buffer 0, step=instance:
    @location(0) char_box   — vec4<i32>  (from Vec4S, 8 bytes as shorts → 16 as i32)
    @location(1) tex_offset — i32        (4 bytes)

Instanced text pipelines (Text2D):
  Buffer 0, step=instance:
    @location(0) pos        — vec2<f32>  (8 bytes)
    @location(1) char_box   — vec4<i32>  (from Vec4S, 8 bytes as shorts → 16 as i32)
    @location(2) tex_offset — i32        (4 bytes)

Instanced text pipelines (Text3D):
  Buffer 0, step=instance:
    @location(0) pos        — vec3<f32>  (12 bytes)
    @location(1) char_box   — vec4<i32>  (from Vec4S, 8 bytes as shorts → 16 as i32)
    @location(2) tex_offset — i32        (4 bytes)

================================================================================================
Migration Notes
================================================================================================

1. GEOMETRY SHADERS → INSTANCED QUADS
   All geometry shaders (Line2D.geom, Line3D.geom, Point2D.geom, Point3D.geom,
   Text2D.geom, Text3D.geom, DashLine2D.geom, FlatFacet.geom) are replaced by
   instanced rendering. Each instance draws 6 vertices (2 triangles forming a quad)
   using vertex_index to select corner positions. This is more efficient than
   geometry shaders on modern GPUs.

   For FlatFacet, the geometry shader averaged normals for flat shading. In WGSL,
   we use @interpolate(flat) which uses the provoking vertex's value. For best
   results, the CPU should provide per-face normals rather than per-vertex normals.

2. TESSELLATION SHADERS → CPU PRE-TESSELLATION
   Bezier.tctrl + Bezier.teval are removed. Bezier curves are tessellated on the
   CPU using Nori.Core's Poly.Flatten() method, which already exists and produces
   line segments. The resulting segments use the same Line2D instanced pipeline.

3. TOPOLOGY CHANGES
   Original GLSL used Lines, Points, Patches, Quads, and TriangleFan primitives.
   WebGPU supports only: PointList, LineList, LineStrip, TriangleList, TriangleStrip.
   - Lines → TriangleList (via instanced quads)
   - Points → TriangleList (via instanced quads)
   - Patches → TriangleList (via CPU tessellation + instanced quads)
   - Quads → TriangleList (CPU converts quads to 2 triangles)
   - TriangleFan → TriangleList (CPU converts fan to triangle list)
   - Triangles → TriangleList (no change)

4. TEXTURE FORMATS
   - Font texture: Uses textureLoad() (integer coordinates) instead of textureSample()
     since the original GLSL used texelFetch() with sampler2DRect.
   - Line-type texture: Uses textureSample() with standard 2D sampler.
